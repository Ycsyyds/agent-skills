# 重点判定标准 + 当天小节模板

## 一、怎么判断一条消息算不算"重点"

目标是从"很杂的群聊"里挑出真正有价值、值得沉淀的信息。靠理解语义，不要只匹配关键词。把每条重点归到下面 5 类之一：

| 类别 | 抓什么信号 |
|------|-----------|
| 🎯 决策/结论 | 群里拍板的事、达成的共识、"就这么定了""那我们用方案 A""结论是…" |
| ✅ 待办/行动项 | 谁要做什么。尽量抓出**负责人 + 事项 + 截止时间**；"我来跟进""@某人 你处理下""周五前给到" |
| 📢 重要通知 | 公告、变更、时间节点、deadline、发版/上线/停服、人事或流程变动 |
| 💡 关键信息/知识 | 以后可复用的结论、经验、排查方法、问答、踩坑记录、重要数据/指标 |
| 🔗 资源 | 群里分享的链接、文档、文件、仓库地址、账号入口等（带上是什么 + 谁发的） |

**不入纪要（直接过滤）**：闲聊、寒暄、表情、接龙、纯情绪、与正事无关的玩笑、机械的"收到/好的/辛苦了"。

**判断要点**：
- **用回复关系和 @提及 串联上下文**：一条"好的，那就这样"要看它回复的是哪条，才知道在拍板什么；"@张三 这个你跟一下"是给张三派的待办。
- **合并同一件事的多条消息**：一个决策往往是几轮讨论的结果，提炼成一条，不要把每句话都记。
- **待办尽量结构化**：能抓到负责人/截止时间就写进去，抓不到就只写事项，别编。
- **把握不准时倾向纳入**：在条目后加"（待确认）"。漏掉一个真待办的代价，比多记一条让人删除要大。
- **简洁**：每条一两句话讲清"是什么"，附上发言人；必要时附原始消息链接/`message_id` 便于回溯。

## 二、当天小节模板

每次运行生成"当天小节"，插到纪要文档锚点之后（即顶部，最新在上）。
**只写当天有内容的类别**——某类没有就整类省略，不要硬留空标题。无任何重点时整节用一行"今日无新增重点"。

```markdown
## {YYYY-MM-DD} 群重点

> 区间 {起}~{止}　|　共 {N} 条重点{；一句话点出今天最值得关注的事，没有就省略}

**🎯 决策/结论**
- {一句话讲清决定了什么}（{相关人}）

**✅ 待办/行动项**
- [ ] {事项} —— 负责人：{姓名}，截止：{时间或"未定"}

**📢 重要通知**
- {通知要点}（{发布人}）

**💡 关键信息/知识**
- {可复用的结论/经验/问答要点}（{来源人}）

**🔗 资源**
- [{标题/说明}]({链接})（{分享人}）
```

跨多天补跑时，**每天生成一个这样的小节**，按"旧→新"顺序逐个插入到同一锚点之后（最后插入的最新日会停在最上方）。

## 三、私信摘要模板

私信比文档更精简，方便手机上一眼扫过。突出"今天有什么要我做/要我知道的"：

```markdown
📋 {群名} · {YYYY-MM-DD} 重点

🎯 决策 {n} 条 ✅ 待办 {n} 条 📢 通知 {n} 条
{用 1~3 行点出最该关注的：比如"待办：周五前你要交设计稿""上线时间改到下周一"}

详见纪要 👉 {纪要文档链接}
```

无新增时私信一行即可：`📋 {群名} · {YYYY-MM-DD}：今日无新增重点。`

## 四、写法约定

- 语气客观，提炼而非搬运原话；不夸张、不臆断。
- 待办用 `- [ ]` 复选框形式，方便你日后在文档里勾掉（这是时间线模式下最轻量的"维护"）。
- 类别 emoji、名称与本文件保持一致，方便跨天扫读和检索。
- 涉及人名：用 `--as user` 拉消息解析出的姓名；只有 open_id 时如实写 open_id 或略去。
