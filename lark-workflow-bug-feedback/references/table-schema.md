# Base 表结构定义

bootstrap 时按下表创建字段。字段名、类型必须与此一致（写记录前仍要 `+field-list` 核对真实字段）。

| 字段名 | 类型 | 谁来填 | 说明 |
|--------|------|--------|------|
| Bug标题 | 文本（主字段） | Agent | 一句话概括问题，便于查重与扫读 |
| 问题描述 | 文本 | Agent | 现象 / 复现步骤 / 期望 vs 实际，多次反馈可补充合并 |
| 类型 | 单选 | Agent | `Bug` / `建议` / `疑问`，默认 `Bug` |
| 涉及模块 | 文本 | Agent | 产品功能模块，**自由文本**。实测模块非常多样（主程序 / 剖面分析·测量 / 兼容性·渲染 / 导入·渲染 / 定位·UI / 渲染·标签 / 导入·格式…），固定单选会频繁漏项、被迫不停加选项，故用文本最省心 |
| 严重程度 | 单选 | Agent | `崩溃` / `严重` / `一般` / `轻微`，由 Agent 据描述判断 |
| 状态 | 单选 | **人工** | `待处理` / `处理中` / `已修复` / `已关闭`，新增默认 `待处理`；**Agent 不修改已有行的状态** |
| 反馈次数 | 数字 | Agent | 新增为 1，命中重复合并时 +1，反映问题热度 |
| 反馈人 | 文本 | Agent | 反馈人姓名列表，合并时追加去重（如 `张三、李四`） |
| 首次反馈时间 | 日期 | Agent | 第一次出现的时间，新增时写入，之后不变 |
| 最近反馈时间 | 日期 | Agent | 每次命中合并都刷新为最新 |
| 原始消息链接 | 文本 | Agent | 来源消息链接 / `message_id`，合并时追加，便于回溯上下文 |
| 备注 | 文本 | 人工 | 处理过程、结论等，Agent 不动 |

## 写入要点

- 只写"存储字段"（文本/数字/单选/日期）。系统字段、公式、附件不在此表，也不直接写。
- 单选字段写入前如选项不存在，按 `lark-base` 字段选项规则处理。
- `状态` 与 `备注` 是人工维护区：新增行时 `状态` 给默认 `待处理`，`备注` 留空，**之后任何运行都不得覆盖人工已填的值**——这是"人机协作维护"的边界，破坏它会让团队的跟踪进度丢失。
- 日期字段用 `YYYY-MM-DD HH:mm:ss` 字符串（见 `lark-base` 错误码 `1254064`）。

## 视图建议（可选）

bootstrap 后可建一个按 `状态` 分组、按 `最近反馈时间` 倒序的视图，方便团队看"待处理 + 最近热点"。非必需，用户要再做。
